# Contributing to Skarva

Start with an issue for large behavior changes. For a bug, include the app version, OS, reproduction steps, and expected result. Use a minimal workflow with invented input; remove keys, email addresses, sensitive prompts, and local file paths before sharing files or screenshots.

See [development setup](docs/DEVELOPMENT.md) for platform dependencies and checks. Keep pull requests focused, explain the user-visible change, and describe how you checked it. Add a regression test when fixing a data-handling or execution bug.

The app aims for a quiet charcoal interface, clear labels, responsive canvas controls, and a short path to the first working workflow. Keep provider and developer details inside the places where users configure or troubleshoot them.

By submitting a contribution, you agree to license it under the repository's [PolyForm Noncommercial 1.0.0 license](LICENSE). Only submit code and assets you have the right to contribute. Keep third-party license and attribution notices with any dependencies or assets you add.
